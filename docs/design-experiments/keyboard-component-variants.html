Component variants

要素単位の比較。現段階では「検証前の音声入力」を誇張しない案を優先する。

1. Color palette

A. Semantic Native

標準色中心。最も安全で長期保守しやすい。

B. Cool Glass Accent

iOS 26 らしさは出るが、ready 感が強くなりやすい。

C. Dark Voice Mode

音声感は強いが、未検証状態には強すぎる。

推奨: A を基準に、B の blue は実機 probe 成功後だけ限定使用。

2. Status and capability row

A. Plain Row

Mic check needed

現状に近い。小さい高さで一番読みやすい。

B. Pill Status

Mic check needed

状態のまとまりは出るが、縦方向の密度が落ちる。

C. Panel Status

Mic check needed

カード感が強く、キーボード領域では重い。

推奨: A。必要なら B を warning/error 時だけ使う。

3. Mic key treatment

A. Neutral Key

未検証段階に最も合う。ready と誤認しにくい。

B. Outline Accent

押せる導線が分かる。probe needed に向く。

C. Primary Accent

録音可能に見える。probe 成功後まで避ける。

推奨: A か B。C は実機で録音/STT が安定してから。

4. Voice activity meter

A. Vertical Bars

現状に近い。音量感と省スペースのバランスが良い。

B. Capsule Progress

capability には向くが、音声波形には見えにくい。

C. Soft Wave

音声感は強いが、小さい領域では装飾に寄りやすい。

推奨: A。C は録音中状態のみに限定するなら候補。
